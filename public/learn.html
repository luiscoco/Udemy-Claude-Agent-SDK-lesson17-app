01

Discover filesystem skills

A skill is a directory containing SKILL.md with a name, description and workflow instructions. The SDK discovers metadata from selected filesystem sources, rather than a programmatic skill-registration API.

02

Load expertise on demand

The model invokes the Skill tool when an available description matches the task. Successful tool evidence and returned skill-specific markers demonstrate observed invocation; the app does not claim to capture every internal prompt block.

03

Choose an invocation scope

Compare omitted skills, "all", an exact-name list and []. When tools is explicit, include Skill. Setting skills auto-adds Skill to allowedTools in the SDK, but explicit tools still governs availability.

04

Read discovery metadata correctly

system/init.skills lists user-invocable skills, including bundled entries, and is not the skills allowlist. A restricted session can still list both classroom skills. user-invocable:false skills are a separate reference case, not created here.

05

Separate direct dispatch from model invocation

Sending /api-review dispatches a user-invocable skill even when it is omitted from the model skills list. Restricting skills is not an OS/file permission boundary. The host separately restricts reads and commands.

06

Troubleshoot with actual evidence

Check cwd and settingSources when skills are missing, description and scope when they are unused, and exact-name syntax when validation fails. The wildcard experiment exercises actual SDK validation before initialization.
