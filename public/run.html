Prepare the TypeScript application

Use Node.js 24+, npm, your own Anthropic key and model access. Windows may also require Git Bash.

cd .\agent-sdk\lesson17-skills

Install and configure your key

Preserve an existing .env or copy the safe example. Add your own key locally, not in the browser or shared source.

if (!(Test-Path .env)) {

notepad .env
03

Start and observe real invocation

Keep the terminal running and open port 3117. Run All, then Omitted. Inspect discovered names, successful Skill calls and the catalogue marker in the actual answer.

npm start
# http://127.0.0.1:3117
04

Compare an exact list and an empty list

Run Allow one, then None. The init list can still contain both classroom names in the restricted session. The plain-summary case does not invoke a skill.

npm run sample:env -- allow-one
npm run sample:env -- none
05

Break discovery and compare direct dispatch

Run No sources and confirm the classroom skills are absent. Then dispatch /api-review with a catalog-only model list and compare the actual response with Skill tool evidence.

npm run sample:env -- no-source
npm run sample:env -- slash
06

Exercise real SDK name validation

Run Invalid wildcard. Expect an SDK validation rejection before system/init, not a fabricated model reply. Then inspect the two safe SKILL.md files and the code walkthrough.

npm run sample:env -- invalid
npm test

Your .env configuration

ANTHROPIC_API_KEY=your_api_key
CLAUDE_MODEL=claude-sonnet-4-6
PORT=3117
# Windows if needed: CLAUDE_CODE_GIT_BASH_PATH=C:/Program Files/Git/bin/bash.exe

The npm scripts load the optional .env explicitly. Existing shell variables take precedence. Restart after edits. No Managed Agents agent or environment ID is needed.

Troubleshooting

If this app is already listening, startup prints its URL. If another service occupies the port, change PORT or stop that service. On Windows set CLAUDE_CODE_GIT_BASH_PATH to the installed bash.exe if necessary. Keep optional npm dependencies enabled. Check key/model access if a real query fails; errors are never replaced by a saved answer.
